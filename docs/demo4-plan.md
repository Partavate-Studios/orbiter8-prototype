# Demo 4 plan

**Status: interviewing.** Nothing is built until this plan is complete and Koda confirms it. Then it's
followed to the end, each step ticked off as it lands.

Branch `demo4`, off `modernize` (2026-11-06). Background: [`design.md`](design.md) (post-Demo 3
design doc), [`design-ideas.md`](design-ideas.md) (Koda's working doc), [`cost-estimates.md`](cost-estimates.md)
(measured costs of play), and the hex galaxy prototype
([hexagon-galaxy-prototype](https://github.com/Zaskoda/hexagon-galaxy-prototype), local copy
`~/dev/hexagon-starfield-demo`).

## Goals (Koda, 2026-11-06)

- The next full demo release: **updated contracts**, and **possibly a move to another network**.
- **As many of the new features as we reasonably can.**
- **The galaxy moves to the hex grid** from the prototype, so it's easy to visualize. New stars are still generated by players' actions: what the player is and does influences how neighbors are generated, as in Demo 3.

## Decisions

| # | Decision | Date |
|---|---|---|
| D1 | **Jump range is a ship upgrade.** The prototype's range setting (how many stars away you can jump) becomes an upgrade that lets a ship jump further. It gets a sci-fi name and in-world reason later. It's the design doc's "Engine Upgrade". | 2026-11-06 |
| D2 | **A fresh universe.** Demo 4 starts a new galaxy on new contracts; nothing migrates from Demo 3, which stays where it is. | 2026-11-06 |
| D3 | **Rewrite the contracts from scratch in the latest Solidity.** Demo 3's contracts were written while learning and have bugs; reuse their rules, not their code. **They must be upgradeable,** so future releases don't need a new universe. (Koda once planned the Diamond pattern; the approach is chosen in the next round.) | 2026-11-06 |
| D4 | **Network-neutral until decided otherwise.** Fable researches Polkadot's very latest features and whether to consider moving; the findings are documented in `docs/research/` and inform the choice. | 2026-11-06 |
| D5 | **Internal milestones, no public release until critical mass.** The dev cycle has milestones; the public release waits until enough of the game is in (what counts is decided below). | 2026-11-06 |
| D6 | **Generation mixes several aspects of the player and the world**, and resists manipulation, including by whoever controls the order transactions are recorded in. | 2026-11-06 |
| D7 | **Two-step exploration if it's clean** (commit, then arrive using randomness nobody could know at commit time), **and only ordinary wallets may play, if that can be enforced.** | 2026-11-06 |
| D8 | **The map can be read anywhere, any time:** the contracts have view methods for any region. **Stars are jittered off the grid** for display, as in the prototype, so the map reads as a star field rather than a lattice. The spiral arms will be revised. | 2026-11-06 |
| D9 | **Store as little on chain as possible.** Defaults come from seeds; only what players change is stored. The same principle drives a new idea, **planet terraforming**: each planet's surface is a map generated from a seed (no storage), and the structures players place are stored on top of it, like Minecraft. | 2026-11-06 |
| D10 | **Range is a straight-line leap.** A ship can jump to any charted, existing star within range on the hex grid, crossing empty cells; no chain of stars is needed (as the prototype's `recomputeReach` does). | 2026-11-06 |
| D11 | **Range starts at 1, and each upgrade adds 1, up to 4.** Each level costs progressively more **in time to earn**, not just in credits: getting from 1 to 2 should take far less play than 3 to 4. The prices must account for a pilot's profit rate rising as they add holds (in the play session, profit per trade grew from about 300 credits at 5 holds to about 15,000 at 250). | 2026-11-06 |
| D12 | **Range never reveals stars.** It only reaches stars already charted. New stars appear only around a star someone arrives at for the first time: its 6 neighbors, never more. | 2026-11-06 |
| D13 | **Research runs on Opus** (Koda's account has few Fable credits). Fable can check it later. | 2026-11-06 |
| D14 | **UUPS proxies** (ERC-1967) with namespaced storage (ERC-7201), one per module, upgraded by an admin multisig. **Pending:** confirmation that this works on Polkadot Hub (the research). | 2026-11-06 |
| D15 | **No wallet-only check.** Since EIP-7702 it can't be enforced, and it would block the smart wallets session keys need. Exploration's own design must prevent re-rolls. | 2026-11-06 |
| D16 | **The spiral can be revised by an upgrade, for uncharted space only.** Decided stars never change. | 2026-11-06 |
| D17 | **Black holes are portals** to another part of space where there's another black hole. A ship can travel to a black hole and orbit it, then choose to leave or to go through. (Details in the next round.) | 2026-11-06 |
| D18 | **Map data loads as the player looks around:** only what's on screen, more as they pan. Whatever is most efficient for reading the map from the chain. | 2026-11-06 |
| D19 | **Terraforming is an advanced feature, designed together later** (Koda wants help building out the concept). Every planet gets a surface seed from the start so it can be added without changing existing planets. | 2026-11-06 |
| D20 | **This run is a chosen subset; the rest goes on a "consider next" list,** revisited in a new interview after this run. Pack in as much as reasonable, low-hanging fruit first. **Some form of battle is absolutely required.** | 2026-11-06 |
| D21 | **Exploring takes one approval.** The jump arrives at once; the ship's **long-range scan** resolves one block later, from that block's hash (unknowable when the jump was sent, so no prediction and no re-rolls). Reading the result is a free view call. It's written to storage by the next move that touches that area, usually the explorer's own next jump or trade, with no separate approval. A scan left untouched past the block-hash window (about 8.5 minutes on 2-second blocks) resolves from a fixed fallback. | 2026-11-06 |
| D22 | **Black holes are permanently paired.** Each one's exit is decided the first time anyone goes through, then fixed for everyone, both ways. The exit is **neither too far nor too close** (a distance band), and **in dead space**: the void between spiral arms, away from charted stars. The traveler's scan charts what's around the exit, so it's the one way to leap into the dark. | 2026-11-06 |
| D23 | **This run's feature list is accepted as proposed** (the items under "This run"; fleets moved out by D26). | 2026-11-06 |
| D24 | **The battle minimum is accepted as a start:** planet defenses; three countering ship weapons (railguns, missiles, point defense) and armor; slow, public sieges; damage that disables systems until repaired; a shipyard repair before attacking again; a Minerva claim with a waiting period. | 2026-11-06 |
| D25 | **Basic graphics are part of this run.** Simpler than before, to be made fancier later, but **an Orbiter 8's look must show what it carries**: a railgun, missile racks, point-defense turrets, armor plating, cargo pods, damage. The same pieces make up the on-chain SVG NFT. | 2026-11-06 |
| D26 | **One ship per pilot, for this run.** Fleets move to "consider next": a remote-control model (the working doc's signal lag and relays) is likely, and needs refining first. Keep this run straightforward, but shape the data so fleets can be added (ships are NFTs; a pilot has an active ship). | 2026-11-06 |
| D27 | **The eight goods:** water ice, metals, rare elements, helium-3, organics, silicon (raw); equipment, electronics (manufactured, by planet type). **Goods are data, not code:** a registry of goods, so crafting's planned expansion can add more without rewriting contracts. | 2026-11-06 |
| D28 | **Black hole exits:** 8 to 24 cells away, the deepest void in that band with no charted star within 2 cells. **The exit is decided when the black hole is created,** not when someone first goes through: its partner cell is reserved as a black hole right away. If someone reaches that area normally before anyone goes through, their scan reveals the partner black hole. (On chain, the band can't be searched cell by cell; a few candidate cells are sampled from the scan's randomness and the deepest one is chosen.) | 2026-11-06 |

## Features: this run and consider next (proposed, for Koda to choose)

Every idea from [`design.md`](design.md), [`design-ideas.md`](design-ideas.md), the contract wish
list in `UPGRADE_NOTES.md` and the play session in [`cost-estimates.md`](cost-estimates.md).
**Proposed, not decided.** The test for "this run": decided already, needed by other features,
hard to add later because it shapes the data, low-hanging, or the battle minimum.

### This run (proposed)

| Feature | Why now |
|---|---|
| Upgradeable contracts, admin roles, access control | Everything later depends on it |
| Hex galaxy: exploration, seeded spiral, region views, black hole portals | Decided |
| Jump range upgrade | Decided |
| Pilots: unique call signs, on-chain name rules, name-change fee | Long wanted; low-hanging |
| Trade fixes: ship must be at the port, a price limit per trade, restocking and margins retuned | Found broken in play; low-hanging |
| More goods (about 8) | Shapes the data; needed by planets and battle supplies |
| Events for every action | Low-hanging; the client updates without reloading |
| Batched reads (a system or region per call) | Needed for map loading |
| Credit sinks: claim fee, name fees, repairs; the port owner's cut as a transfer | Low-hanging; the economy inflates without them |
| On-chain SVG ship NFTs that show upgrades | Koda wants it soon; self-contained |
| Session keys (approve once per session) | Needed for one-approval play; fewer wallet popups |
| Planets, linear tech tree: Citadel, Colony, Station, Port, Yards, Armory; colonists and production | Battle needs planets worth taking and defending |
| **Battle minimum:** planet defenses; a few ship weapons that counter each other; armor; slow, public sieges; damage to ship systems instead of a reset; repairs before attacking again; claims with a waiting period | Required |

### Consider next (proposed)

- **Battle, more:** overheating, experience, booby traps, ship-to-ship combat, asteroid attacks
- **Social:** corporations, corporate law, protected zones, pirates and bands, bounties
- **Economy and building:** supply routes, crafting, builders (probes, autofactories), negotiated prices, branching tech tree
- **Fleets:** several ships per pilot, with remote control (signal lag, relays); refine first (D26)
- **Bigger systems:** terraforming (designed together), digital pilots (cubes, lag, relays, escape pods, cube hunting), tractor beams
- **Parked:** portals between networks, new ship types and aliens, tokenized goods, hidden information with ZK proofs, invite-only cubes, star-system weapons, Minerva's hidden agenda, planet maintenance, vanity upgrades, alignment, corporate taxes; client extras (soundtrack folders, re-skinning, ENS names)
